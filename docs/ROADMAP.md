# 반성 계모임 관리 웹앱 개발 로드맵

## 개요

- **프로젝트명**: 반성 (계모임 관리 웹앱)
- **목적**: 계모임 회원의 월별 납입 현황 추적 및 지출 내역 투명화
- **대상 사용자**: 계모임 회원(일반), 계모임 운영자(관리자)
- **전체 기간**: 약 7~9주 (팀 규모 및 작업 속도에 따라 조정)
- **작성일**: 2026-03-25

---

## 제품 비전 및 목표

**핵심 가치 제안**
- 계모임 회원 누구나 납입 현황을 실시간으로 투명하게 확인
- 관리자의 수작업(엑셀, 카카오톡 공지)을 웹앱으로 대체
- 별도 서버·스토리지 없이 Notion을 DB로 활용하여 운영 비용 최소화

**성공 지표 (KPI)**
| 지표 | 목표 |
|------|------|
| 사용자 페이지 4개 완성 | Phase 1 완료 기준 |
| 관리자 페이지 완성 | Phase 2 완료 기준 |
| Notion 연동 전체 완료 | Phase 5 완료 기준 |
| Vercel 배포 완료 | Phase 6 완료 기준 |

---

## 전체 로드맵 개요

```
[1단계: UI/UX 먼저] ──────────────────────────────────────► 사용자 확인 포인트
 Phase 0        Phase 1              Phase 2
 환경·구조 세팅   사용자 페이지 4개 UI   관리자 페이지 UI
 (1~2일)        (1~2주)              (1주)
                                              ↓
                                     [사용자 확인·승인]
                                              ↓
[2단계: 기능 구현] ──────────────────────────────────────────► 서비스 오픈

 (3~5일)        (1~2주)        (1주)          (2~3일)
```

## 개발 전략: UI 우선 → 기능 구현

> **핵심 원칙**: UI/UX를 Mock 데이터로 먼저 완성하고 사용자의 확인·승인을 받은 뒤, API와 DB 연동을 구현합니다. 이 방식은 방향 전환 비용을 최소화하고, 초기 단계에서 불필요한 백엔드 공수를 줄입니다.

- 메인 페이지와 목록 페이지는 SSR 또는 ISR 적용으로 초기 로딩 최적화
- 관리자 접근 제어는 미들웨어(`middleware.ts`)에서 중앙 관리

## 가정사항 (Assumptions)

> PRD에 명시되지 않은 항목에 대해 아래와 같이 가정하고 진행합니다. 팀에서 검토 후 조정이 필요합니다.

1. **월 납입 금액은 고정**: 회원별 다른 금액이 아닌 전체 공통 금액으로 가정 (PRD에 금액 설정 기능 없음)
2. **비밀번호 암호화**: NextAuth.js Credentials Provider에서 bcrypt 등으로 비밀번호 해싱 처리 필요 — Notion DB에는 해시값 저장
3. **게시판 권한**: PRD상 "본인 글 수정/삭제"만 명시 → 관리자는 모든 글 수정/삭제 가능으로 가정
4. **지출 등록 권한**: PRD에 명시 없음 → 관리자만 등록 가능으로 가정
5. **페이지네이션**: Notion API의 페이지당 최대 100건 제한 고려 필요
6. **Notion 이미지 URL 만료**: Notion 파일 첨부 URL은 1시간 후 만료 → Phase 5에서 처리 방안 결정 필요
